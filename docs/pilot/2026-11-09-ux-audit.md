# UX audit and improvement plan — 9 November 2026 (rebased on `codex/mobile-polish`)

**Scope:** Campus Recall as deployed (https://campusrecall.indiasouthcentral.cloudapp.azure.com), checked against the `codex/mobile-polish` commit `6f21ac9`, which is not deployed yet. I audited it as a first-time student on a phone (375 × 812) and on a laptop.

**Method:**
- a heuristic evaluation (Nielsen's 10 heuristics, Krug's laws);
- a cognitive walkthrough of the first five minutes;
- a WCAG 2.2 AA spot check;
- a code read of every screen;
- a cited deep-research report: [`research/2026-11-09-product-campus-recall-ux.md`](../../research/2026-11-09-product-campus-recall-ux.md). It covers five areas, each researched by one agent, and gives a confidence level for every claim.

**Severity:** 4 catastrophic, 3 major, 2 minor, 1 cosmetic.

## Score: 5 / 10 deployed → about 6 / 10 with mobile polish

Six of the ten quick checks fail on the deployed site. Mobile polish fixes the scroll part of navigation and two phone details, so the score rises slightly. The flow, status and error problems remain.

### Already fixed on `codex/mobile-polish`
- **Scroll on screen change:** a new screen now starts at the top. The audit measured the old behaviour on the live site: the Library opened at a scroll position of 453 px and Search at 130 px.
- **Status filter:** now 16 px text and 44 px tall, so iPhones no longer zoom in when it's tapped.
- **Screen edges:** left and right safe-area padding on the content, the top bar, the bottom bar, the viewer and dialogs.
- **Landscape phones:** a touch-screen phone in landscape (up to 900 px wide and 520 px tall) now uses the bottom navigation.
- **Cloud lists:** cloud library rows and cloud search results have readable titles and buttons that wrap properly.
- **Sign-out checkbox:** now a proper 20 px checkbox.

### Kept as is, on purpose
- **Delete stays a confirmation, with no Undo.** Spec S3 makes a local delete immediate and permanent. Research: Apple's guidelines, Material and NN/g agree on a confirmation for uncommon, irreversible actions (High).
- **The 445 MB download stays an explicit tap** (S7). The research supports this: Chrome itself requires a user action before a model download.

## Decisions for you (blocked by existing tests or the spec)
Following the repo rule, I won't edit existing tests to make these pass. Each one needs a deliberate spec and test change if you want it:

1. **Remove the welcome dialog after the landing page.** NN/g's onboarding research says tutorials didn't improve success and made tasks feel harder, and comparable apps open straight into the library. It's pinned by `tests/e2e/landing.spec.ts` (lines 19–22, 71–74).
2. **Hide the filter chips on an empty library.** It's pinned by `tests/e2e/chaitanya-fixes.spec.ts` (test #16).
3. **A 7-day "Recently deleted" area instead of permanent delete.** Apple Notes, Keep and Raindrop all do this. It would change spec S3.
4. **Split the model download.** A small text pack would come first, with images, speech and OCR later. This is a large engine change; the research supports it (Play Asset Delivery, Apple Background Assets).
5. **A title-only search before setup, clearly labelled.** This is new behaviour that the spec doesn't cover.

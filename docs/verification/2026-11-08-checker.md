## Failures retained and corrected

1. Independent inspection found that existing browser readiness checks need `curl`, QA helpers need Git and the frozen retrieval manifest, and formatting needs `.prettierrc.json`. The test image now includes those dependencies and exact configuration. Original tests, styles and rules were not rewritten to pass.
2. An initial execution failed formatting because its configuration file had been omitted. The wrapper exited nonzero. Adding the existing file corrected packaging; it did not reformat the application.
3. At the original Docker allocation of 7168 MiB, 107 fast and 37 browser tests passed, but actual-model acceptance had 9 failures and 2 passes. Failed cases raised `QuotaExceededError` while caching assets. Chromium's private-profile quota is derived from 15–20% of physical RAM divided by three, independently of disk capacity or the masked storage estimate. See the [exact Chromium quota implementation](https://chromium.googlesource.com/chromium/src/+/refs/tags/156.0.8078.4/storage/browser/quota/quota_settings.cc). The test wrapper now checks Docker memory before a long run and exits with instructions when insufficient.
4. With 10240 MiB allocated, five measured fresh-context quotas ranged above the full 445,160,734-byte asset payload. DevTools reported quota overrides inactive. The unchanged full suites then passed. No unlimited-storage flag, quota override, reduced model, frozen-threshold change or skipped case was used.
5. Temporary browser smoke automation initially raced the welcome modal, then assumed a collapsed cloud title was visible. Those harness failures remain in private logs; waits and actual accessible controls were corrected, and exact downloaded hashes remained the functional assertion.

## Comparable local-first apps: first run, optional sync, deleting

*Method note: every app observation below comes from that vendor's help pages, or from third-party write-ups, read on 2026-11-09. No app was installed and run for this section. UIs change, so treat each observation as dated 2026-11-09 unless another date is given.*

**First run and empty libraries.** The local-first tools start with a choice of where the data lives, not with a pitch. According to [Obsidian Help](https://obsidian.md/help/Getting+started/Create+a+vault) (accessed 2026-11-09, confidence: Medium, tier: Primary), a first launch asks for exactly one thing: create a new empty vault or open an existing folder as a vault. Logseq also asks you to open or create a graph. However, a 2022 forum thread reports a new user who spent more than 4.5 hours building pages in the built-in demo graph without understanding where files were written ([Logseq forum](https://discuss.logseq.com/t/first-launch-confusion-for-new-users-no-information-on-what-a-graph-is-how-files-are-read-from-written-to/4297), accessed 2026-11-09, confidence: Low, tier: **Low**). Cloud-backed libraries seed starter content instead. According to [Readwise Help](https://help.readwise.io/article/163-how-do-i-get-started-with-reader) (accessed 2026-11-09, confidence: Medium, tier: Primary), Reader puts a "Getting Started with Reader" document in the library by default. Notion opens a learn-by-doing "Getting Started" page and a checklist after asking about intent, as described by [Appcues GoodUX](https://goodux.appcues.com/blog/notions-lightweight-onboarding) and a Packt book (accessed 2026-11-09, confidence: Medium, tier: Established/Low). mymind's stated philosophy avoids dropdowns and filters altogether ([mymind manifesto](https://mymind.com/manifesto), accessed 2026-11-09, confidence: Low, tier: Primary). For empty states, [NN/g, Kaplan 2021](https://www.nngroup.com/articles/empty-state-interface-design/) (accessed 2026-11-09, confidence: Medium, tier: Established) gives three guidelines: communicate system status, give learning cues, and offer direct pathways to key tasks. It cites demo data as one route to "safe exploration." It also notes that an empty filtered result leaves users wondering whether they set the wrong filters.

**Onboarding research.** In [NN/g's tutorial study](https://www.nngroup.com/articles/mobile-tutorials/) (Kendrick, March 2020; accessed 2026-11-09, confidence: Medium, tier: Established), 70 participants used four iOS apps. Those who went through deck-of-cards tutorials reached 91% task success against 94% for those who skipped them (not significant, p=0.443). The tutorial group also rated the tasks as harder (SEQ 4.92 vs 5.49, p=0.047). In a companion article, [NN/g](https://www.nngroup.com/articles/mobile-app-onboarding/) (June 2020; confidence: Medium, tier: Established) advises skipping onboarding where possible and avoiding promotional feature tours at first launch. It says onboarding is justified only when the app needs user information, depends on user context, or has unfamiliar workflows. Industry figures disagree with each other, and every one comes from a vendor. Userpilot reports an average checklist completion of 19.2% (median 10.1%) across 188 companies. Appcues' blog sets a 60–70% "solid target" for onboarding completion ([Appcues](https://appcues.com/blog/onboarding-optimization), accessed 2026-11-09, confidence: Low, tier: **Low**/vendor). Pendo defines time-to-value as the days from first login to completing a "core event" ([Pendo](https://www.pendo.io/product-benchmarks/), accessed 2026-11-09, confidence: Low, tier: vendor). I could not verify its best-in-class figure of 0.2 days.

**Optional sync and accounts.** Most apps in this set make sync a separate, opt-in step, and several ask for an explicit encryption decision before anything is uploaded. According to [Obsidian Help](https://obsidian.md/help/sync/setup) (accessed 2026-11-09, confidence: Medium, tier: Primary), first-device setup has 27 numbered sub-steps in five groups: log in, enable the core plugin, create a remote vault with a region and an encryption password, connect, and adjust settings. The guide explicitly says "Do not start syncing yet." Upload begins only when the user presses Start Syncing after choosing selective-sync options. Status is shown as a single status-bar icon, a green check when "Fully Synced," whose menu also holds the sync log, version history and deleted files. Logseq Sync uses a separate graph password, set when you create a remote graph, and Logseq does not store that password ([Logseq docs](https://raw.githubusercontent.com/logseq/docs/master/pages/Logseq%20Sync.md), accessed 2026-11-09, confidence: Medium, tier: Primary). Anytype defaults to its own network. Local-only and self-hosted modes are set from a gear icon on the onboarding screen, and the vault key is a 12-word phrase that Anytype cannot reset ([Anytype docs](https://doc.anytype.io/anytype-docs/advanced/data-and-security/self-hosting/local-only), accessed 2026-11-09, confidence: Medium, tier: Primary). In Bear, iCloud sync is a single Pro toggle tied to the Apple ID ([Bear FAQ](https://bear.app/faq/features-and-price-of-bear-pro/), accessed 2026-11-09, confidence: Medium, tier: Primary). Day One encrypts new journals end to end by default, and the setting cannot be reverted ([Day One guide](https://dayoneapp.com/guides/settings/how-to-set-up-end-to-end-encryption/), accessed 2026-11-09, confidence: Medium, tier: Primary). Standard Notes can be used "totally offline without an account" ([Standard Notes Help](https://StandardNotes.org/help/59/can-i-use-standard-notes-totally-offline), accessed 2026-11-09, confidence: Medium, tier: Primary). Joplin exposes a Synchronisation Status page with item counts ([Joplin docs](https://joplinapp.org/help/apps/sync/nextcloud), accessed 2026-11-09, confidence: Medium, tier: Primary).

**Local-first principles.** [Ink & Switch, Kleppmann et al., 2019](https://www.inkandswitch.com/essay/local-first/) (accessed 2026-11-09, confidence: Medium, tier: Primary, peer-reviewed at Onward! 2019) lists seven ideals, including "the network is optional" and user ownership. It asks apps to "make clear to users when the data is stored only on their device versus being transmitted to a backend," and it criticizes alarming "offline!" warnings. A third-party summary of Eileen Wagner's "The UX of Local-First" talk at Local-First Conf argues for picking either explicit sync (freshness timestamps, push/pull indicators) or fully non-intrusive sync, never a mix. It also notes that Dropbox's six sync icons confuse users ([second-brain summary](https://second-brain-nuxt.vercel.app/the-ux-of-local-first), accessed 2026-11-09, confidence: Low, tier: **Low**).

**Deleting.** Most of these apps use soft delete rather than confirm-then-erase. Apple Notes keeps deleted notes in Recently Deleted for 30 days ([Apple Support](https://support.apple.com/en-gb/guide/icloud/mm2f42f05cb9), accessed 2026-11-09, confidence: Medium, tier: Primary). Google Keep keeps them in the bin for 7 days ([Google Keep Help](https://support.google.com/keep/answer/6262770?hl=en-GB), accessed 2026-11-09, confidence: Medium, tier: Primary). Raindrop keeps items in Trash until the user empties it ([Raindrop Help](https://help.raindrop.io/troubleshooting/lost-data), accessed 2026-11-09, confidence: Medium, tier: Primary). Obsidian offers three settings: system trash, the vault's `.trash` folder, or permanent deletion ([Obsidian Help](https://obsidian.md/help/settings), accessed 2026-11-09, confidence: Medium, tier: Primary). Design guidance points the same way. Apple's HIG says to avoid alerts for common, undoable actions "even when they're destructive" and to keep alerts for uncommon, irreversible ones ([Apple HIG Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts), accessed 2026-11-09). Material says confirmation "isn't necessary when the consequences of an action are reversible" ([Material](https://m2.material.io/design/communication/confirmation-acknowledgement.html), accessed 2026-11-09). [NN/g, Nielsen](https://www.nngroup.com/articles/confirmation-dialog/) (2018, reviewed 2026; accessed 2026-11-09) warns that overused confirmations get clicked through, asks for specific labels such as "Delete file," and advises going "to great lengths to provide undo." Together these three make the confirm-only-when-irreversible rule High confidence (tier: Primary/Established).

> Conflicts noted: Onboarding completion benchmarks disagree widely: Userpilot puts average checklist completion at about 19%, while Appcues sets a 60–70% target. The likely reason is different definitions and samples, so neither figure is reliable. The Wagner talk summary dates the talk 2026-02-22, but the Local-First Conf 2025 schedule lists it as a 2025 talk; I treat it as the 2025 talk. Standard Notes' help page says no account is needed, but an App Store developer reply says an account is now required; which is current is unresolved.
> Gaps: No sources found for the current first-run screens of Google Photos, Microsoft OneNote, Day One or mymind, or for Anytype's bin behaviour. I found no peer-reviewed "aha moment" or time-to-value study, only vendor definitions. The current Material 3 snackbar page did not render, so the undo-snackbar duration of 4–10 s comes only from a third-party mirror (Low).

**Implications for Campus Recall (synthesis, not sourced fact).** The comparable local-first apps open with one decision or one starter document, not a pitch repeated in a modal. That suggests dropping the welcome modal and giving the empty library a single primary action, with filter chips hidden until items exist. Obsidian's sync flow pauses before the first upload and shows status as one quiet icon. This supports keeping Campus Recall's "Include this device's library" as an explicit consent step, but merging sign-in and consent into one screen and labelling "Use Local only" as a positive choice rather than a cancel. Apple, Material and NN/g all reserve confirmation dialogs for irreversible actions. Because the spec makes local delete immediate and permanent, a specific dialog ("Delete 'notes.pdf' from this device? This can't be undone.") is defensible, but the cloud delete should end with a visible success message, and the team should weigh whether a short undo window would serve students better than the current permanent delete.

## Phone platform and Indian context

**Storage durability.** Safari's "7-day cap" dates from March 2020. It deletes script-writable storage (IndexedDB, LocalStorage, service worker registrations and Cache) after seven days of Safari use with no user interaction on the site. WebKit's own clarification says Home Screen web apps "have their own counter of days of use" that only advances when the app itself is used, and that any first-party data loss there would be "a serious bug" [WebKit blog, 2020-03-24](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/) (accessed 2026-11-09, confidence: High, tier: Primary). web.dev says the policy "does not apply to installed PWAs that have been added to the home screen" [web.dev Storage for the web, 2024 update](https://web.dev/articles/storage-for-the-web) (accessed 2026-11-09, confidence: High, tier: Primary). MDN (modified 2026-01-05) still describes the seven-day rule as active whenever cross-site tracking prevention is on, but does not say whether Home Screen apps are exempt [MDN Storage quotas](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria) (accessed 2026-11-09, confidence: High, tier: Primary).

WebKit's August 2023 policy (Safari 17 / iOS 17) changed three things. Browser apps get an origin quota of up to 60% of disk and an overall quota of up to 80%. Home Screen web apps get "the same origin quota and overall quota" as the browser. The old prompt for more space is gone. Under the new policy, eviction is LRU per origin, triggered by quota, system pressure or ITP inactivity. Origins in persistent mode are excluded. WebKit grants `persist()` by heuristics "like whether the website is opened as a Home Screen Web App" [WebKit Updates to Storage Policy, 2023-08-10](https://webkit.org/blog/14403/updates-to-storage-policy/) (accessed 2026-11-09, confidence: High, tier: Primary). MDN confirms the 60% figure and that Safari now decides persistence silently, with no prompt (same MDN source).

A Home Screen app on iOS keeps its storage separate from Safari. A WebKit bug from 2018 documents this [WebKit Bug 181849](https://bugs.webkit.org/show_bug.cgi?id=181849) (accessed 2026-11-09, confidence: Low, tier: Primary but dated). web.dev's reference to a "separate storage container" is consistent with it. This suggests that models downloaded in a Safari tab would have to be downloaded again after installing.

Chrome and other Chromium browsers never show a prompt for `persist()`. They grant it silently based on site engagement, whether the site is installed or bookmarked, and whether it has notification permission. A denied request can be tried again later [web.dev Persistent storage](https://web.dev/articles/persistent-storage) (accessed 2026-11-09, confidence: High, tier: Primary). The original Chromium intent named "added to home screen" as a signal [blink-dev Intent to Experiment: Durable Storage](https://groups.google.com/a/chromium.org/d/msg/blink-dev/5Sihi1iAXYc/wnvNDFIPAQAJ) (accessed 2026-11-09, tier: Primary, 2016). Firefox shows the user a permission popup (web.dev; MDN). Chrome allows up to 60% of disk per origin and evicts the whole least-recently-used origin, with IndexedDB and Cache deleted together, unless the origin is persistent (MDN; web.dev).

**Install promotion.** According to MDN browser-compat-data, `beforeinstallprompt` is supported in Chrome 61+ (desktop and Android), Edge, Opera and Samsung Internet 8.0+. It is not supported in Firefox or in Safari on macOS and iOS. MDN marks it "Limited availability", with the spec still a WICG incubation [MDN beforeinstallprompt, modified 2026-10-26](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeinstallprompt_event) (accessed 2026-11-09, confidence: High, tier: Primary). Chrome's current criteria have four parts. The user must have clicked or tapped the page and spent at least 30 seconds on it. The site must use HTTPS. The manifest needs `name`/`short_name`, 192px and 512px icons, `start_url`, and a `display` of standalone or similar. `prefer_related_applications` must not be true [web.dev install criteria](https://web.dev/articles/install-criteria) (accessed 2026-11-09, confidence: Medium, tier: Primary). Chrome dropped the service-worker `fetch` handler requirement for menu install in Chrome 108 (mobile) and 112 (desktop) [Chrome blog](https://developer.chrome.com/blog/update-install-criteria) (accessed 2026-11-09, confidence: Medium, tier: Primary). web.dev's guidance on promotion is to show custom UI only after the event fires and after "strong interest signals", ideally right after a completed task. It also says to keep the promotion out of the way of next steps and to listen for `appinstalled` [web.dev Patterns for promoting install](https://web.dev/articles/promote-install) (accessed 2026-11-09, confidence: Medium, tier: Primary).

On iOS 26, "every website added to the Home Screen opens as a web app" by default. Users can switch off the "Open as Web App" toggle, and manifest icons still apply [WebKit WWDC25, 2025-06-09](https://webkit.org/blog/16993/news-from-wwdc25-web-technology-coming-this-fall-in-safari-26-beta/) (accessed 2026-11-09, confidence: High, tier: Primary). iDownloadBlog reports the same [iDownloadBlog](https://www.idownloadblog.com/?p=1042117) (accessed 2026-11-09, tier: Established). Install on iOS is still manual through Share, then Add to Home Screen.

**Web Share Target.** Web Share Target works in Chrome for Android 76+ and Chrome desktop 89+, plus Edge, Opera and Samsung Internet. Firefox and Safari (macOS and iOS) do not support it, and the WebKit bug (194593) is still open [MDN BCD share_target](https://github.com/mdn/browser-compat-data/blob/main/manifests/webapp/share_target.json) (accessed 2026-11-09, confidence: High, tier: Primary). A December 2025 developer note reached the same conclusion for iOS [plyr.fm research note](https://tangled.org/zzstoatzz.io/plyr.fm/blob/main/docs/research/2025-12-19-web-share-target-ios-pwa.md) (**Low tier**). The app must be installed before it appears as a share target. Files require `method: POST`, `enctype: multipart/form-data` and an `accept` list of MIME types or extensions. A service worker `fetch` handler has to read `formData()`, which means the flow can work offline. On Android the `url` field arrives empty [Chrome Developers Web Share Target](https://developer.chrome.com/docs/capabilities/web-apis/web-share-target) (accessed 2026-11-09, confidence: Medium, tier: Primary).

**theme_color and background_color.** On Android, `theme_color` colours the status bar and `background_color` fills the splash screen before the CSS loads [web.dev Learn PWA: App design](https://web.dev/learn/pwa/app-design) (accessed 2026-11-09, confidence: Medium, tier: Primary). A per-page `<meta name="theme-color">` overrides the manifest and can carry `prefers-color-scheme` media queries [MDN theme_color, modified 2025-12-18](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference/theme_color) (accessed 2026-11-09, confidence: High, tier: Primary). In Safari 26, browser tabs reportedly take the toolbar tint from the html/body background, and `theme-color` is used only by installed web apps [Apple Developer Forums](https://developer.apple.com/forums/thread/801239); [MDN BCD PR 28503](https://github.com/mdn/browser-compat-data/pull/28503) (accessed 2026-11-09, confidence: Low, tier: Low). A Glide community user reports that the `black-translucent` status-bar style broke in iOS 26.1 (**Low tier**).

**Indian phone context.** StatCounter's India mobile web traffic for September 2026 is 93.89% Android and 6.05% iOS [StatCounter](https://gs.statcounter.com/os-market-share/mobile/india) (accessed 2026-11-09, confidence: High, tier: Established). Shipment data agrees: Apple held 9% of 2025 units according to Counterpoint and 10% according to IDC, with 28–29% of value. Premium phones above ₹30,000 were 22% of shipments [GSMArena on IDC](https://www.gsmarena.com/indian_smartphone_market_remains_flat_in_2025_signals_structural_changes-news-71575.php); [Business Today on Counterpoint](https://www.businesstoday.in/technology/news/story/over-1-in-5-smartphones-sold-in-india-cost-more-than-rs-30000-apple-sees-highest-ever-value-share-report-514235-2026-02-02) (accessed 2026-11-09, confidence: High, tier: Established). Memory price rises in 2026 pushed budget makers back toward 4GB-RAM and 64–128GB-storage models. Counterpoint saw launches of 4+64, 4+128 and 6+128 variants roughly double in Q1 2026 [Counterpoint launch tracker](https://counterpointresearch.com/cn/reports/India-Smartphone-Launches-Q1-2026-OEMs-Re-calibrate-Portfolios-Amid-Rising-BOM-Costs) (accessed 2026-11-09, confidence: Medium, tier: Established).

TRAI's FY2025-26 indicators (released 2026-10-05) put average wireless data revenue at ₹8.02 per GB, down from ₹8.97. Average use was 25.51 GB per subscriber per month [TRAI PR 127/2026](https://trai.gov.in/sites/default/files/2026-10/PR_No127of2026.pdf); [TelecomTalk, 2026-10-06](https://telecomtalk.info/revenue-per-gb-data-drops-fy26-trai/1012551/) (accessed 2026-11-09, confidence: High, tier: Primary/Established). At that rate, 445 MB costs about ₹3.5. The more important limit is the 1.5–2 GB daily caps on the common prepaid plans; after the July 2024 hikes, Jio's 1.5 GB/day plan costs ₹299 for 28 days [The Week, 2024-07-01](https://www.theweek.in/news/biz-tech/2024/07/01/jio-airtel-vodafone-idea-tariff-hike-detailed-comparison-of-old-revised-price.amp.html) (accessed 2026-11-09, confidence: Medium, tier: Established). Chrome's Lite mode data saver was switched off in Chrome 100 (March 2022). Android's system Data Saver still exists [Android Police](https://www.androidpolice.com/google-is-retiring-chromes-data-saving-lite-mode-next-month-saying-its-no-longer-necessary/) (accessed 2026-11-09, confidence: Medium, tier: Established). IIT Gandhinagar's campus and hostels are described as having Wi-Fi everywhere, but reported speeds range from 4 Mbps to several hundred Mbps [Careers360](https://www.careers360.com/university/indian-institute-of-technology-gandhinagar/facilities); [Shiksha reviews](https://www.shiksha.com/college/iit-gandhinagar-indian-institute-of-technology-32705/reviews-2) (accessed 2026-11-09, confidence: Low, tier: Low).

> Conflicts noted: For Safari's quota, web.dev (2024) still reports about 1 GB with a 200 MB-increment prompt, while WebKit (2023) and MDN (2026) say 60% of disk with no prompt. The web.dev figure appears to be pre-iOS 17, so WebKit's is used here. On the 7-day cap, web.dev says Home Screen apps are exempt, while WebKit (2020) says they have their own use-based counter. In practice these mean the same thing for an app the student opens. MDN does not address the point. Firt.dev once reported service-worker storage being shared with Safari on iOS, which conflicts with WebKit bug 181849. India's 2025 shipment share for Apple is 9% (Counterpoint) or 10% (IDC).
> Gaps: No official Apple documentation of iOS 26 `theme_color` or splash behaviour was found. There is no public shipment split by RAM or storage tier for India. No official IIT Gandhinagar network specification was found. No sources were found on Android Data Saver usage rates among Indian students. Chromium's current `persist()` heuristic code was not verified beyond the documentation.

**Implications for Campus Recall (synthesis).** About 94% of Indian mobile traffic is Android Chromium, where `persist()` is granted silently and installation is a strong signal. This suggests calling `persist()` automatically after install, and after the first successful save, rather than relying on a manual button, and showing the result in plain words. On iOS, students should be steered to Add to Home Screen *before* the 445 MB model download, because Home Screen storage is separate from Safari's and is protected from the 7-day cap. The data cost of the download is small (about ₹3.5), but it takes a large bite of a 1.5 GB daily allowance and of a 64–128 GB phone, so the app should say "use campus Wi-Fi" and show the size upfront. A Web Share Target for "save from WhatsApp/Gallery" would reach most users on Android but none on iOS, so it is worth adding as an Android enhancement with the in-app picker kept as the universal path. Finally, `theme_color` should change from #245edb to the paper colour (#f4f1ea), with a dark-scheme meta variant, so the Android status bar and splash match the app.

## First run with a large one-time download

**Where and when to ask.** Platform guidance for on-device AI points to asking at the moment of use, not on a settings page. According to web.dev, apps should "only download what's necessary" and wait until there is "reasonable certainty the AI features will be used". Its example starts a type-ahead model download only when the user begins typing. The same article says to warn users before large model downloads [web.dev, Client-side AI performance](https://web.dev/articles/client-side-ai-performance) (accessed 2026-11-09, confidence: Medium, tier: Primary). Chrome's built-in AI APIs make this a technical rule as well. When a model's status is `downloadable` or `downloading`, `create()` runs only after a user activation such as a click, tap or key press [Chrome for Developers, Get started with built-in AI](https://developer.chrome.com/docs/ai/get-started) (accessed 2026-11-09, confidence: Medium, tier: Primary). The Translator API works the same way: language packs are "downloaded on demand", the first time a site uses the pair [Chrome for Developers, Translator API](https://developer.chrome.com/docs/ai/translator-api) (accessed 2026-11-09, confidence: Medium, tier: Primary). The Whisper Web demo for Transformers.js also downloads its model lazily. Its worker loads the model only on the first transcription request, and the interface labels the progress "Loading model files... (only run once)" with one bar per file [xenova/whisper-web source, AudioManager.tsx and worker.js](https://github.com/xenova/whisper-web) (accessed 2026-11-09, confidence: Medium, tier: Low, since it is a demo repository whose last commit was in 2023).

Research on permission prompts points the same way. Nielsen Norman Group reports that requests tied to an action the user just took cause less surprise than requests the system raises on its own, and that users were 12% more likely to grant a request when given a reason [NN/g, Permission Requests](https://www.nngroup.com/articles/permission-requests/) (accessed 2026-11-09, confidence: Medium, tier: Established). A USENIX Security 2021 study found that asking in context "always has a positive effect" on grant rates [Elbitar et al., USENIX Security 2021](https://trust.cispa.saarland/publication/elbitar-usenix-21/elbitar-usenix-21.pdf) (accessed 2026-11-09, confidence: Medium, tier: Primary; it predates the 2022 window). Together these support an in-context ask over a settings-only control (confidence: High for "ask in context"). A permission prompt is only a stand-in for a download prompt, so this conclusion is inference.

**Communicating size, network, time and control.** Chrome's guidance calls it "best practice to alert the user to the time required" for model downloads. It says to show a progress bar driven by `downloadprogress` events (0 to 1), switch to an indeterminate state while the model is extracted and loaded, and show only the remaining bytes if the user returns in the middle of a download [Chrome for Developers, Inform users of model download](https://developer.chrome.com/docs/ai/inform-users-of-model-download) (accessed 2026-11-09, confidence: High, tier: Primary). web.dev agrees and adds "time remaining". It also notes that desktop users tolerate large downloads better than mobile users, and that after a dropped connection the app should "inform the user... and continue the download when the connection is restored" [web.dev](https://web.dev/articles/client-side-ai-performance) (accessed 2026-11-09, confidence: Medium, tier: Primary). NN/g recommends a percent-done indicator for any wait of 10 seconds or more [NN/g, Progress Indicators](https://www.nngroup.com/articles/progress-indicators/) (accessed 2026-11-09, confidence: Medium, tier: Established). For cancel and resume, Chrome's model-caching guide shows chunked parallel fetches (six requests by default) with a progress callback and an `AbortSignal` for cancelling. It recommends the Cache API and `navigator.storage.persist()`, and warns that unpersisted storage "may be cleared under storage pressure" [Chrome for Developers, Cache models in the browser](https://developer.chrome.com/docs/ai/cache-models) (accessed 2026-11-09, confidence: Medium, tier: Primary). Chrome itself downloads Gemini Nano only on an "unlimited data or an unmetered connection" with at least 22 GB free [Chrome get-started](https://developer.chrome.com/docs/ai/get-started) (accessed 2026-11-09, confidence: Medium, tier: Primary). Google Translate offers a "Data usage > Downloaded languages" setting with two choices: "Ask before downloading" or "Use Wi-Fi or mobile network" [Google Translate Help](https://support.google.com/translate/answer/6142473?hl=en). Google Maps auto-updates offline areas only on Wi-Fi [Google Maps Help](https://support.google.com/gmm/answer/6291838?hl=en) (both accessed 2026-11-09, confidence: Medium, tier: Primary).

The Network Information API is not a reliable signal. According to MDN's browser-compat-data, Safari and iOS have never supported `navigator.connection`. Firefox removed it (desktop after version 32, Android after version 99). Chrome and Edge support `effectiveType`/`downlink` (Chrome 61+, Android 38+) and `saveData` (Chrome 65+). `type` (`wifi`/`cellular`) is marked experimental: it is supported on Chrome for Android, on desktop only on ChromeOS, and not in Edge [MDN browser-compat-data, NetworkInformation.json](https://github.com/mdn/browser-compat-data/blob/main/api/NetworkInformation.json); [MDN, Network Information API](https://developer.mozilla.org/en-US/docs/Web/API/Network_Information_API) (accessed 2026-11-09, confidence: High, tier: Primary). `saveData` is also usually false in practice. Chrome for Android removed Lite mode in Chrome 100 (March 2022), which a blink-dev participant described as the only trigger for `Save-Data: on` [blink-dev, Save-Data client hint thread](https://groups.google.com/a/chromium.org/g/blink-dev/c/HR7tWmewbSA/m/9UrOsc9AAAAJ); [Android Police](https://www.androidpolice.com/google-is-retiring-chromes-data-saving-lite-mode-next-month-saying-its-no-longer-necessary/) (accessed 2026-11-09, confidence: Medium, tier: Primary/Established). The Background Fetch API would allow downloads that survive closing the tab, but it is experimental and Chromium-only (Chrome 74+). In contrast, `storage.persist()` (Safari 15.2+) and `storage.estimate()` (Safari 17+) work in every major engine [MDN BCD](https://github.com/mdn/browser-compat-data) (accessed 2026-11-09, confidence: Medium, tier: Primary).

**What to offer before the download completes.** web.dev advises letting "key features function even if the AI model isn't fully loaded yet" [web.dev](https://web.dev/articles/client-side-ai-performance). Chrome describes a hybrid approach in which a cloud model serves requests until the local model is ready, citing Miravia [Chrome inform-users](https://developer.chrome.com/docs/ai/inform-users-of-model-download) (both accessed 2026-11-09, confidence: Medium, tier: Primary). Campus Recall promises that search stays on the device, so cloud fallback is not an option. A local keyword or title search is the closest equivalent; that conclusion is inference. Comparable products split downloads into stages. Play Asset Delivery has three modes: `install-time`, `fast-follow` (downloads after install without blocking the app) and `on-demand` [Android Developers, Play Asset Delivery](https://developer.android.com/guide/playcore/asset-delivery). Apple's Background Assets framework has Essential, Prefetch and On-demand packs [Apple WWDC25 session 325](https://developer.apple.com/videos/play/wwdc2025/325/) (accessed 2026-11-09, confidence: High, tier: Primary). Google Translate lets users "upgrade" to a higher-quality language pack later [Google Translate Help](https://support.google.com/translate/answer/6142473?hl=en). Apple Intelligence downloads automatically after an OS update and needs up to 8 GB (up to 14 GB on newer devices). It becomes unavailable while a new Siri language is downloading [Apple Support 121115](https://support.apple.com/en-us/121115) (accessed 2026-11-09, confidence: Medium, tier: Primary). Apple Photos shows that partial results are acceptable to users: forum reports describe search results with a note that more results will appear once indexing completes [Apple Community / MacRumors threads via search](https://discussions.apple.com/thread/256112241) (accessed 2026-11-09, confidence: Low, tier: Low).

**Evidence on drop-off.** All of the quantitative evidence is old and indirect. Google Play reported a 1% drop in install conversion for every 6 MB added to apps under 100 MB, and about 2.5% gained per 10 MB removed in emerging markets. For games of 500 to 3,000 MB, the effect was only 1% per 200 MB [Google Play, Shrinking APKs, growing installs (2017)](https://medium.com/googleplaydev/shrinking-apks-growing-installs-5d3fcba23ce2). Android's current game-size documentation repeats the 6 MB figure [Android Developers, game size](https://developer.android.com/games/optimize/game-size) (accessed 2026-11-09, confidence: Medium, tier: Primary). A 2018 W3C workshop paper from Poki covered 174 desktop web games. At a 10 MB initial download, about 80% of US players got to play, compared with 70% in Brazil and under 60% in Egypt [W3C Games Workshop, Size Matters](https://www.w3.org/2018/12/games-workshop/papers/size-matters.html) (accessed 2026-11-09, confidence: Low, tier: Primary, single dataset, pre-2022). These numbers suggest that drop-off grows with size and is worse on weaker networks. None of them measures an opt-in download after install of roughly 445 MB.

> Conflicts noted: web.dev says connection type "won't actually indicate whether the user is on Wifi or data", but MDN BCD lists `type` (`wifi`/`cellular`) as supported on Chrome for Android. The likely explanation is that web.dev means `effectiveType`, or that it is generalising across browsers. In either case, `type` is not available on iOS or desktop. A SitePen blog claims Firefox for Android (68+) supports the API, while MDN BCD shows support removed in Firefox Android 99; I use MDN. Apple's storage figure changed between versions (an earlier search snippet said 7 GB; the current page says up to 8 GB or 14 GB), which reflects the timing of each OS release.
> Gaps: There is no published 2022 to 2026 measurement of drop-off caused by an optional in-app model download. Apple dictation language download UX was not found. No first-party description of Google Translate's or Maps' size and time disclosure UI was found. No pause/resume UX guidance for web model downloads exists beyond chunking and AbortSignal. I could not inspect the WebLLM Chat progress UI; its API exposes progress (0 to 1), elapsed time and status text.

**Implications for Campus Recall (synthesis).** The download offer should appear inline where the failed search happened, replacing the red error. It should be a one-tap card with a reason, the size (about 445 MB), Wi-Fi advice and an estimated time. That matches Chrome's user-activation model and the evidence on in-context requests. Because `navigator.connection.type` is missing on iOS and desktop, the app should state the size plainly and ask the student, rather than trying to detect metered data. Splitting the download into a small text-embedding model first, with vision, speech and OCR packs fetched after it or on demand, would mirror the fast-follow and on-demand patterns. Until the models arrive, a local title and keyword search, clearly labelled as partial, would let students see value before they commit to the full download.
